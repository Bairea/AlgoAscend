这是一个非常好的面试策略问题。面试官考察的**不是"你会不会调库"**，而是**"你是否理解底层原理，并能在合适场景做出合理权衡"**。

### 1. 排序解法分析

先回答你的具体问题：排序解法**可行但不是最优**。

```python
class Solution:
    def findTheDifference(self, s: str, t: str) -> str:
        s_sorted = sorted(s)
        t_sorted = sorted(t)
        for i in range(len(s)):
            if s_sorted[i] != t_sorted[i]:
                return t_sorted[i]
        return t_sorted[-1]  # 多出的一定在末尾
```

| 维度 | 排序解法 | XOR 解法 | Counter 解法 |
| :--- | :--- | :--- | :--- |
| 时间复杂度 | O(N log N) | **O(N)** | O(N) |
| 空间复杂度 | O(N) | **O(1)** | O(N) |
| 代码量 | 中等 | 极少 | 极少 |
| 面试印象 | "会基础算法" | "懂位运算技巧" | "熟悉Python工具" |

> ⚠️ 排序是 O(N log N)，而本题存在 O(N) 甚至 O(1) 空间的解法。如果你主动选择排序，面试官大概率会追问："有没有更优的？"——**你必须能答出 XOR 或计数法才算过关。**

### 2. 面试中"用内置工具 vs 手写算法"的判断框架

核心原则：**先用最优手写解法证明能力，再用内置工具展示工程素养。**

#### ✅ 推荐的安全策略（三步走）

```
第一步：给出最优手写解 → 证明算法能力
第二步：提及内置工具   → 证明工程意识  
第三步：对比分析       → 证明深度理解
```

**以本题为例的话术：**

> "这道题最优解是异或，时间 O(N) 空间 O(1)。（写出XOR解法）
> 
> 实际工程中我会直接用 `Counter(t) - Counter(s)`，一行搞定且可读性好，但它是 O(N) 空间。
> 
> 排序也能做，但 O(N log N) 在这里没必要，因为不要求保留顺序信息。"

#### 🎯 什么时候可以放心用内置方法？

| 场景 | 可以用 | 原因 |
| :--- | :--- | :--- |
| 题目核心难点不在该操作 | ✅ | 如用 `sorted()` 做预处理，重点在后续逻辑 |
| 内置方法是业界标准解 | ✅ | 如 `bisect`, `heapq`, `defaultdict` |
| 面试官明确说"假设XX已实现" | ✅ | 聚焦更高层设计 |
| 该操作本身就是考点 | ❌ | 如考排序时不能用 `sorted()` |
| 有更优手写解而你只会调库 | ❌ | 暴露知识盲区 |

#### 🚫 危险信号

-   **只给内置解，无法解释底层原理** → 面试官认为你只会背API
-   **用了内置解但不知道其复杂度** → 比不用还差
-   **简单题直接调库，没有提到更优手写方案** → 错失展示机会

### 3. 针对本题的最佳面试回答模板

```python
# 【首选】展示算法功底
def findTheDifference(self, s: str, t: str) -> str:
    res = 0
    for c in s + t:
        res ^= ord(c)
    return chr(res)

# 【补充说明】展示工程思维
# "生产环境中，如果可读性优先，我也会考虑：
#  - Counter(t) - Counter(s)  → 语义清晰，O(N)时间/空间
#  - sum(ord(c) for c in t) - sum(ord(c) for c in s) → 简洁
#  但排序 O(NlogN) 在此题不是最优选择，因为问题本质是频次差异而非顺序比较。"
```

### 💡 总结一句话

> **面试中，内置工具是你的"第二武器"，不是"唯一武器"。** 先用手写最优解拿到算法分，再用内置工具展示你知道"真实世界怎么写"，最后点明各方案的 trade-off。这个节奏下，无论面试官侧重算法还是工程，你都稳了。
